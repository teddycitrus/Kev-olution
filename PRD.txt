KEV-EVOLVE PRODUCT REQUIREMENT DOCUMENT (PRD)

1. PROJECT OVERVIEW
Project Name: Kev-Evolve
Objective: Build a high-performance, real-time autonomous research and evolutionary code-optimization harness inspired by RSI-top, OpenEvolve, and ShinkaEvolve.
Core Problem: Standard coding agents fail during complex research or optimization tasks because they get trapped in local maxima and flood their context windows with failed execution traces, leading to reasoning degradation.
Solution: Kev-Evolve combines Jared Palmer's sub-20ms Kev decision engine with a Directed Acyclic Graph (DAG) trajectory memory store. Kev acts as a high-speed router to evaluate candidate mutation strategies in milliseconds, pruning bad search paths before executing expensive sandboxes and triggering automated "Paradigm Shift" mutations when performance plateaus.

2. KEY SYSTEM ARCHITECTURE & COMPONENTS

* DAG Trajectory Memory Store (src/harness/graphStore.ts): Replaces flat linear context windows with a Directed Acyclic Graph tracking code iterations, parent-child lineages, execution metrics, and compressed failure summaries.
* Multi-Fidelity Sandbox Evaluator (src/harness/evaluator.ts): Tiered sandbox runner for fast AST validation (Tier 1), mini-workload execution profiling (Tier 2), and full benchmark hardware verification (Tier 3).
* Kev SystemOne Routing Client (src/harness/kevClient.ts): High-speed API client that queries Kev models in ~10-20ms to evaluate AST diffs and score proposed trajectory paths.
* Plateau Detector & Paradigm Shift Agent (src/agents/mutator.ts & src/agents/reflector.ts): Monitors metric progress across generations. When progress stalls for N cycles, it purges local branch history and forces a major structural refactor (e.g., warp-level memory tiling or memory layout shifts).
* Live Terminal Dashboard (src/ui/dashboard.ts): Rich CLI interface built with Ink or Blessed displaying live search trees, real-time TFLOPS/latency line graphs, decision latency, and cost savings telemetry.

3. KEV SYSTEMONE API CONFIGURATION

* Endpoint URL: https://yohann-60613--kev-demo.modal.run/v1/systemone
* Required Headers:
  * "Authorization": "Bearer <KEV_API_KEY>"
  * "Content-Type": "application/json"
* Request Body Payload:
  * "model": "kev-9b" or "kev-27b"
* Usage Guidelines & Rate Limit Management:
  * Environment Variable: Store key in .env as KEV_API_KEY=<key>.
  * Daily Limits: Exactly 1000 calls for kev-9b and 200 calls for kev-27b.
  * Routing Rules: Use kev-9b for high-frequency search space pruning, trajectory evaluation, and AST filtering. Use kev-27b strictly when the Plateau Detector fires a "Paradigm Shift" event for deep recovery reasoning.
  * Quota Tracking: Implement local counter state in kevClient.ts to log daily usage and prevent exceeding quota limits.
